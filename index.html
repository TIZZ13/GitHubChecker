  2. Нет ли в репозитории секретов?
  3. Поверит ли этому незнакомый человек?

Что проверяется в режиме автора

Безопасность 25

Секреты в коде, .env в репозитории, приватные ключи, конфиги с паролями.

Запуск 20

Инструкция «как запустить», манифест проекта, lockfile, точка входа, CI.

Качество 15

Тесты, линтер, проверка тестов в CI, гигантские файлы в репозитории.

Репозиторий 15

Лицензия, описание, темы, README на английском, картинки.

Продукт 15

Демо-ссылка, релизы, CHANGELOG, шаблоны issue, документация.

Доверие 10

Контрольные суммы, политика безопасности, CONTRIBUTING, контакты.

Два режима проверки

Автор проекта. 23 правила о том, что мешает проекту выглядеть готовым, и готовые промпты для твоего ИИ-агента.

Скачиваю. 21 правило о том, стоит ли доверять готовым файлам: что известно о коде, есть ли контрольные суммы и предупреждения о поведении. Это не проверка на вирусы и не гарантия безопасности.

Правила подстраиваются под тип проекта: библиотеке и настольной программе не нужно живое демо, а маленькому шуточному проекту не снижают балл за отсутствие CI. Неприменимые проверки не штрафуют и перечислены как «Не оценивалось». Оценка пересчитывается из уже загруженных данных: режим можно переключить после проверки, без новых запросов.

Как это работает

  1. Читает публичные данные. Сайт делает несколько запросов к GitHub API: описание, файлы, README, релизы и немного исходников для проверки рисков.
  2. Прогоняет правила. Это детерминированные проверки, а не ИИ: одинаковый репозиторий всегда получает одинаковый балл.
  3. Объясняет и даёт промпт. Каждая проблема — человеческим языком, с готовым текстом для твоего агента.

Приватность

Ничего не отправляется никуда, кроме api.github.com. Нет аналитики, нет аккаунтов, нет базы данных. Токен, если добавишь, хранится только в твоём браузере. Найденные секреты не показываются в интерфейсе и не логируются.

What gets checked in author mode

Security 25

Secrets in code, committed .env, private keys, configs with passwords.

Runnable 20

Install/run instructions, manifest, lockfile, entry point, CI.

Quality 15

Tests, linter, tests running in CI, huge files in the repo.

Repository 15

License, description, topics, English README, images.

Product 15

Demo link, releases, changelog, issue templates, docs.

Trust 10

Checksums, security policy, contributing guide, contacts.

Two audit modes

I am the author. 23 rules about what keeps the project from looking ready, plus ready-to-paste prompts for your AI agent.

I am downloading. 21 rules about whether the ready-made files are worth trusting: what is known about the code, whether checksums and behaviour warnings exist. This is not a virus scan and not a safety guarantee.

The rules adjust to the kind of project: a library or a desktop app does not need a live demo, and a small joke project is not marked down for missing CI. Checks that do not apply are not scored and are listed as “Not scored”. The score is recomputed from data already loaded, so you can switch modes after an audit without new requests.

How it works

  1. Reads public data. A few GitHub API requests: description, file tree, README, releases and a few source files for the risk scan.
  2. Runs rules. Deterministic checks, not AI: the same repository always gets the same score.
  3. Explains and hands you a prompt. Every issue is plain language, with text you can paste into your agent.

Privacy

Nothing is sent anywhere except api.github.com. No analytics, no accounts, no database. A token, if you add one, stays in your browser. Detected secrets are never rendered or logged.

Настройки

Нужен только для приватных репозиториев и лимита 5000 запросов в час вместо 60. Хранится в localStorage этого браузера и уходит только на api.github.com. Нужен scope public_repo.
